# 视频号下载按博主昵称分类设计

## 目标

视频号视频下载完成后，在下载根目录下按照博主视频号昵称建立一级目录，最终路径为：

```text
<下载根目录>/<博主目录>/<原有视频文件名>.mp4
```

当前安装版本的下载根目录继续使用：

```text
D:\owner\socialMedia\Y2A-Auto\爆款视频参考\shipinghao
```

## 范围

- 视频号后端下载任务使用新的博主目录规则。
- 项目内置默认配置采用新的目录模板。
- 当前 `dist/v260714/app/config.yaml` 同步采用新的目录模板，使现有安装立即生效。
- 已经下载的文件不在本次改动中重新分类。
- 已停用的自动视频转换任务继续保持停用。

## 目录名称规则

新增模板变量 `author_folder`，由后端统一计算：

1. 优先使用去除首尾空白后的 `feed.Contact.Nickname`。
2. 昵称为空时，使用去除首尾空白后的 `feed.Contact.Username`。
3. 昵称和视频号 ID 都为空时，使用固定名称 `未知视频号`。
4. 最终目录名称继续交给现有 `FilenameProcessor` 清理 Windows 非法字符、保留名称和过长名称。

同名昵称共用同一个目录。目录中发生文件名冲突时，继续使用项目现有的重名处理逻辑。

## 配置与兼容性

默认文件名模板从：

```yaml
filenameTemplate: "{{filename}}_{{spec}}"
```

调整为：

```yaml
filenameTemplate: "{{author_folder}}/{{filename}}_{{spec}}"
```

保留已有的 `author` 模板变量，避免破坏用户自定义模板。新增的 `author_folder` 只提供经过兜底选择的目录名称。

已有用户如果明确配置了自定义 `download.filenameTemplate`，程序继续尊重该配置，不在启动时强制覆盖。当前安装版本的配置文件属于本次明确授权的变更范围，将单独调整为新模板。

## 数据流

1. 视频 Feed 数据进入文件名生成逻辑。
2. 后端从 `Nickname`、`Username`、`未知视频号` 中选出博主目录原始值。
3. 模板渲染器把 `author_folder`、`filename`、`spec` 等变量替换为实际值。
4. `FilenameProcessor` 拆分目录和文件名，并清理非法字符。
5. 批量或单个下载任务在 `<下载根目录>/<博主目录>` 下保存文件。

## 错误与安全处理

- 博主昵称中的路径分隔符和 Windows 非法字符不得创建额外目录层级。
- `.`、`..`、Windows 保留设备名等危险或非法目录名由现有清理逻辑处理。
- 空昵称不会让视频回落到下载根目录。
- 目录创建或文件写入失败时，继续沿用现有下载任务错误处理和日志。

## 测试策略

先添加失败测试，再进行实现：

- 昵称存在时，模板结果包含昵称目录。
- 昵称为空且视频号 ID 存在时，模板结果包含 ID 目录。
- 昵称和视频号 ID 都为空时，模板结果包含 `未知视频号` 目录。
- 昵称带 Windows 非法字符时，生成安全的单层目录。
- 同一博主的不同视频进入同一目录。
- 保留原有文件后缀和同名文件去重行为。
- 执行相关包测试，并执行完整 `go test ./...` 回归测试。
